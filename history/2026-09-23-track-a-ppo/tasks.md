# tasks — track-a-ppo (ROADMAP Phase 3)

관심사 단위로 나눈 Phase 다. **ROADMAP 의 Phase 와 층위가 다르다** — 이 문서의 P1~P7 은
ROADMAP Phase 3 **안**의 작업 단위다.

**의존 관계**

```
P1 예산·골격 ─┬─▶ P2 진영 분할 ─┬─▶ P3 기준선·평가기 ─┐
              │                  │                      ├─▶ P6 학습·튜닝 ─▶ P7 보고·이관
              └─▶ P4 롤아웃 ─────┴─▶ P5 PPO 코어 ───────┘
```

`P4 → P5` 가 특히 정확해야 한다. 롤아웃이 틀린 채로 PPO 를 얹으면 이후의 모든 실패가
알고리즘 탓으로 오진된다 (`plan.md` §13).

## P4. 롤아웃 — 테스트를 구현보다 먼저 ✅

> next-step autoreset 의 버려지는 스텝과 truncation 부트스트랩. **조용히 틀리는 지점이다.**
> (FR-2, FR-4, FR-5, M3-f / `plan.md` §6.3, §7)

- [x] `test_rollout.py` 를 **먼저** 썼다. 31개는 서버 없이 돌고 (`ScriptedEnv` 가 `PikaEnv` 의
      오토리셋 상태기계만 흉내낸다), 마지막 하나만 실제 서버에 붙어 계약의 접합을 지킨다:
  - [x] 버려지는 스텝이 `valid=False` 로 표시된다 (랠리 길이 3 → `[1,1,1,0]` 주기)
  - [x] 버려지는 스텝의 advantage·가치 목표가 손실에 **0 기여**한다 (그 자리를 ±1e9 로
        바꿔도 마스크 안 통계가 불변이다). 쓰레기가 **앞으로 새지도 않는다** — 종료 스텝의
        `cut=1` 이 재귀를 끊으므로 그 스텝의 보상을 1000 으로 키워도 앞쪽 advantage 가 같다
  - [x] `terminated` 는 부트스트랩하지 않고 `truncated` 는 `V(s_final)` 로 한다.

## P5. PPO 코어 ✅

> 상대가 누군지 모르는 순수 알고리즘. Phase 4 가 그대로 재사용한다.
> (FR-1, NFR-4 / `plan.md` §8)

- [x] `ppo.py` — clipped surrogate · 가치 손실 · 엔트로피 보너스 · grad clip.
      **가치 손실은 순수 MSE 다** — `0.5 × MSE × value_coef` 관습을 쓰면 표(§8.1)의 0.5 가
      실제로는 0.25 를 뜻하게 된다. 가치 손실 클리핑은 넣지 않았다 (표에 없다)

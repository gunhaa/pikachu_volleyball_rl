# 표적 케이스 — 입력 생성기 (d). (plan.md §6.4 / tasks.md P7)
#
# 무작위 입력이 도달하지 못하는 분기를 상태를 직접 심어서 겨냥한다.
# JS 오라클(tools/js-oracle/targeted.mjs) 과 Kotlin 하네스(TargetedCases.kt) 가
# **이 파일 하나**를 함께 읽는다. 같은 표를 양쪽에 두 번 적으면 반드시 어긋난다.
#
# 문법
#   case <이름> <입력생성기> <시드> <프레임수>
#     set <필드> <정수>
#
#   - 입력생성기: uniform | biased | fsm
#   - set 은 PikaPhysics 생성 **직후**, 프레임 0 **이전**에 적용된다.
#   - 필드명은 State Spec (proto/state_spec.proto) 의 이름을 그대로 쓴다. bool 은 0/1.
#
# ⚠️ 라운드 리셋이 일어나면 리셋 대상 필드는 원래대로 돌아간다.
#    `game_ended` · `diving_direction` · `lying_down_duration_left` · `is_winner` ·
#    `computer_where_to_stand_by` 와 공의 회전·펀치이펙트는 리셋 대상이 아니라 살아남는다.

# ── 경기 종료 전이 (state 5/6) ────────────────────────────────────────────────
# 물리 엔진은 game_ended 를 스스로 세팅하지 않는다 — 그건 pikavolley.js 의 일이다
# (ROADMAP Phase 2). 따라서 이 분기는 **어떤 입력 시퀀스로도 도달할 수 없고**,
# 상태를 심는 것 말고는 방법이 없다. 표적 케이스가 필요한 정확한 이유다.
case game-end-p1-wins uniform 101 150
  set player1.game_ended 1
  set player1.is_winner 1
  set player2.game_ended 1
  set player2.is_winner 0

case game-end-p2-wins biased 102 150
  set player1.game_ended 1
  set player1.is_winner 0
  set player2.game_ended 1
  set player2.is_winner 1

# 경기 종료가 선언될 때 플레이어가 서 있지 않은 경우 (state != 0 이라 승리 모션 진입이 미뤄진다)
case game-end-while-airborne fsm 103 150
  set player1.game_ended 1
  set player1.is_winner 1
  set player1.state 1
  set player1.y_velocity -16
  set player2.game_ended 1
  set player2.state 3
  set player2.diving_direction -1
  set player2.y_velocity -5

# ── hyper ball 글리치 ────────────────────────────────────────────────────────
# fine_rotation 이 정확히 50 이면 보정 분기 두 개를 모두 비켜가 rotation 이 5 에 고착된다.
# x_velocity 가 0 이면 fine_rotation 이 갱신되지 않아 충돌 전까지 계속 5 에 머문다.
case hyper-ball-stuck uniform 201 150
  set ball.fine_rotation 50
  set ball.x_velocity 0

case hyper-ball-fsm fsm 202 300
  set ball.fine_rotation 50
  set ball.x_velocity 0

# 보정 분기 양쪽 (음수 → +50, 50 초과 → -50)
case fine-rotation-wrap-negative uniform 203 120
  set ball.fine_rotation 0
  set ball.x_velocity -20

case fine-rotation-wrap-positive uniform 204 120
  set ball.fine_rotation 49
  set ball.x_velocity 20

# ── 네트 기둥 충돌 ───────────────────────────────────────────────────────────
# 기둥 윗면(y <= 192): 공이 네트 위에 얹혀 오래 튄다.
# 이 배치는 calculateExpectedLandingPointXFor 의 루프도 400회 이상 돌게 만든다.
case net-pillar-top uniform 301 240
  set ball.x 216
  set ball.y 180
  set ball.x_velocity 0
  set ball.y_velocity 0

# 기둥 옆면(y > 192) — 왼쪽에서 접근
case net-pillar-left-side uniform 302 120
  set ball.x 200
  set ball.y 220
  set ball.x_velocity -3
  set ball.y_velocity 0

# 기둥 옆면 — 오른쪽에서 접근
case net-pillar-right-side uniform 303 120
  set ball.x 232
  set ball.y 220
  set ball.x_velocity 3
  set ball.y_velocity 0

# ── 다이빙 후 경직 중 충돌 ───────────────────────────────────────────────────

# 공 충돌 처리는 그대로 돌아간다. 누운 채로 공에 맞는 경로.
